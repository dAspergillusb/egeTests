# Docker & Alembic

The project can be run as a reproducible Docker Compose stack with PostgreSQL and Alembic migrations.

## Services

`docker-compose.yml` defines three services:

- `db` — PostgreSQL 16
- `migrations` — runs Alembic migrations for all three application databases
- `app` — starts the FastAPI application after migrations complete successfully

The application currently uses three PostgreSQL databases:

- `users_main`
- `informatics_main`
- `archive_databases`

Each database has its own Alembic history because the project uses separate SQLAlchemy metadata objects for these domains.

## Environment

Copy the example configuration:

```bash
cp .env.example .env
```

At minimum, provide secure values for:

```env
DB_PASSWORD=change-me
SECRET_KEY=replace-with-a-random-secret-at-least-32-characters-long
```

For Docker Compose, `DB_HOST` is supplied automatically as `db`.

## Start the stack

```bash
docker compose up --build
```

On the first PostgreSQL initialization, `docker/init-databases.sh` creates the three application databases.

The `migrations` service then runs:

```bash
alembic -c alembic-users.ini upgrade head
alembic -c alembic-informatics.ini upgrade head
alembic -c alembic-archive.ini upgrade head
```

The FastAPI container starts only after all migrations complete successfully.

The application is available at:

```text
http://localhost:8000
```

## Run migrations manually

Users database:

```bash
alembic -c alembic-users.ini upgrade head
```

Informatics database:

```bash
alembic -c alembic-informatics.ini upgrade head
```

Archive database:

```bash
alembic -c alembic-archive.ini upgrade head
```

## Create a new migration

Choose the database whose models changed.

Example for the users database:

```bash
alembic -c alembic-users.ini revision --autogenerate -m "add user field"
```

For informatics:

```bash
alembic -c alembic-informatics.ini revision --autogenerate -m "change question schema"
```

For archive:

```bash
alembic -c alembic-archive.ini revision --autogenerate -m "update archive schema"
```

Review every autogenerated migration before applying it.

## Notes

Docker startup sets `INITIATED_DBS=True` so schema creation is handled by Alembic rather than the legacy `create_all()` initialization path.

Fresh Docker databases intentionally do not seed the public demo credentials from `database.csv`. User/bootstrap data should be created explicitly instead of creating weak default accounts during infrastructure startup.
